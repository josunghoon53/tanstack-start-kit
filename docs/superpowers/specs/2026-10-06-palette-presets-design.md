# 팔레트 프리셋 설계 — 사이드바 컬러 + 메인 최소 포인트

> 이전 포인트색 5종(블루/그린/퍼플/로즈/오렌지, [2026-10-05 계획](../plans/2026-10-05-style-color-split.md))을 대체한다.
> 승인된 시안: [`assets/color-combos-preview.html`](./assets/color-combos-preview.html)의 **모드 2**("사이드바 컬러 + 메인 최소 포인트").
> 파생 규칙(`derive()`)은 이 시안의 스크립트가 기준이다.
>
> **2026-10-09 갱신:** 처음 넣은 12종 중 `pop`·`pop-red` 2종만 남기고 10종을 뺐다(아래 "프리셋 정리" 참고).
> 이후 프리셋은 하나씩 추가한다.

## 결정 사항

- 테마 축은 그대로 둘이다. 스타일(`data-style`: clean/soft/editorial/crisp)은 모양과 글꼴만 바꾸고 바뀌지 않았다.
  색 축(`data-color`)만 "작은 포인트색 5종"에서 "3색 팔레트 프리셋"으로 바뀌었다(처음 12종 → 2026-10-09에 2종으로 정리).
- 프리셋을 고르지 않으면 기본(무채색)이다. 기본의 모든 토큰 값은 이전 무채색과 같다(화면 변화 없음).
- **사이드바만 팔레트 면을 갖는다.** 메인의 큰 면(페이지, 카드, 표, 본문·제목·KPI 글자, 테두리, 차트 일반 막대,
  보조 버튼)은 어떤 프리셋에서도 무채색이다.
- 메인에서 팔레트가 보이는 곳은 주요 버튼 면, 링크, 주간 매출 막대의 강조 1개, 활성 탭/세그먼트, 포커스 링(모두 주색),
  칩/배지(옅은 색 면 + 진한 글자)뿐이다.

## 역할 배정 — 상대 휘도

세 색을 WCAG 상대 휘도로 정렬해 가장 어두운 색 = 주색, 중간 = 포인트, 가장 밝은 색 = 옅은 색으로 정한다.
원본 자료의 역할 라벨은 쓰지 않는다. 두 색의 휘도 차가 0.05 미만이면 프리셋별로 순서를 명시할 수 있게 했지만,
남은 2종 모두 순서가 분명해서(가장 가까운 경우: `pop`의 라임 0.843 vs 아이보리 0.906, 차 0.063) 오버라이드는 없다.

| id        | 이름               | 주색           | 포인트       | 옅은 색            |
| --------- | ------------------ | -------------- | ------------ | ------------------ |
| `pop`     | 톡톡 튀는 스타일   | 코발트 #003FE2 | 라임 #D6FC43 | 아이보리 #F6F4F0   |
| `pop-red` | 선명한 레드 포인트 | 잉크 #1D2330   | 레드 #E84635 | 오프화이트 #F4F1E8 |

## 프리셋 정리 (2026-10-09)

처음엔 12종을 넣었지만 `pop`·`pop-red`만 남기고 `dreamy`(플럼/모브/애프리콧), `nature`(모스/라일락/미스트),
`energy`(인디고/오렌지/옐로), `pop-color`(바이올렛/코랄/레몬), `sweet`(라즈베리/피스타치오/옐로),
`cozy`(코코아/피치/바닐라), `retro`(그린/탠저린/블루), `rest`(말차/살구/크림), `elegant`(버건디/핑크/아이보리),
`clear`(틸/라벤더/아이스) 10종을 뺐다.

**이유(사용자 피드백):**

- 차분한 "무드" 팔레트(모스·말차·코코아·플럼·버건디·틸 등)는 사이드바 면이 탁해 보였다.
- 파스텔·중간 톤 포인트(라일락·모브·핑크·라벤더·피치·살구 등)는 활성 메뉴 박스가 면과 잘 구분되지 않았다
  (숫자상 3:1은 넘어도 눈으로는 흐릿했다).
- 인디고 + 오렌지처럼 강한 보색 쌍은 경계가 떨려 보였다(vibration).
- 남긴 2종은 사이드바 면이 깨끗하고(선명한 코발트 / 무채색에 가까운 잉크) 포인트가 선명하며 면과의 대비가 크다
  (포인트/주색: `pop` 6.36, `pop-red` 4.01).

**새 프리셋 지침:** 사이드바 면은 깨끗한 진한 색(무채색에 가깝거나, 선명하되 탁하지 않은 색), 포인트는 선명한 색으로
면과 대비가 커야 한다. 탁한 중간 톤 면, 파스텔 포인트, 채도 높은 보색 정면 대비는 피한다. 추가 절차는 `AGENTS.md`
테마 절의 "프리셋 추가 방법"을 따른다(데이터 + CSS 블록 + ko/en 이름 → 대비 테스트가 자동으로 검사).

저장값 호환: 빠진 id가 `theme-color`에 남아 있어도 `parseThemeColor`와 초기화 스크립트가 `THEME_COLORS`에 없는 값으로 보고
기본(무채색)으로 조용히 돌아간다(`theme.test.ts`, `color-theme-picker.test.tsx`가 확인).

## 파생 토큰

모두 미리 계산해 `src/config/theme.ts`의 `PALETTE_PRESETS`에 hex로 저장하고, `src/styles.css`의
`:root[data-color='…']` 블록에 같은 값을 `--pal-*`로 둔다(값 일치는 `theme.test.ts`가 확인).

| 토큰                  | 규칙                                                                       | 쓰는 곳                                                                  |
| --------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `main` / `--pal-main` | 주색. 흰 글자 4.5:1 미만이면 검정 쪽으로 5%씩 어둡게(지금 프리셋은 불필요) | 사이드바 면, `--primary`, `--ring`, `--chart-1`                          |
| `mainFg`              | 항상 `#FFFFFF`                                                             | `--primary-foreground`                                                   |
| `accent`              | 포인트                                                                     | 사이드바 활성 메뉴 박스·로고 박스(`--sidebar-primary`), `--sidebar-ring` |
| `accentFg`            | `#111111`/`#FFFFFF` 중 대비 높은 쪽(지금 프리셋은 모두 `#111111`)          | `--sidebar-primary-foreground`                                           |
| `soft`                | 옅은 색                                                                    | `--chip`(secondary 배지)                                                 |
| `softFg`              | 중립 잉크 `#1F2024`, 4.5:1 미만이면 어둡게(불필요)                         | `--chip-foreground`                                                      |
| `sidebarText`         | 옅은 색을 흰색 쪽으로 40%, 4.5:1 미만이면 더 흰색 쪽으로                   | `--sidebar-foreground`(비활성 메뉴)                                      |
| `sidebarStrong`       | 옅은 색을 흰색 쪽으로 70%, 7:1 목표(못 미치면 흰색)                        | `--sidebar-accent-foreground`(브랜드·이름·호버 글자)                     |
| `sidebarLine`         | 주색을 흰색 쪽으로 16%                                                     | `--sidebar-accent`(호버 면), `--sidebar-border`                          |

시안의 `sdm`(섹션 라벨 흐린 글자)은 따로 저장하지 않았다. 앱은 원래 `text-sidebar-foreground/70`을 쓰고,
이게 시안의 "비활성 글자를 면 쪽으로 30%" 규칙과 같은 결과다.

## 대비 (`src/config/palette-contrast.test.ts`)

| 검사                        | 기준  | 가장 낮은 값    |
| --------------------------- | ----- | --------------- |
| 흰 글자 / 주색              | ≥ 4.5 | `pop` 7.48      |
| 사이드바 비활성 글자 / 주색 | ≥ 4.5 | `pop` 7.06      |
| 활성 메뉴 글자 / 포인트     | ≥ 4.5 | `pop-red` 4.82  |
| 칩 글자 / 옅은 색           | ≥ 4.5 | `pop-red` 14.41 |
| 포인트 / 주색 (비텍스트)    | ≥ 3   | `pop-red` 4.01  |

테스트는 `THEME_COLORS` 전부를 돌기 때문에 프리셋을 추가하면 자동으로 같은 검사를 받는다.

## 앱 쪽 변경

- `--ah`/`--ae` 계산식을 걷어내고, 기본 `:root`는 이전 `--ae: 0`일 때와 같은 값을 직접 적었다.
- 공용 `:root[data-color]` 매핑 블록이 `--pal-*`를 shadcn 토큰에 연결한다. 큰 면 토큰은 매핑하지 않는다(테스트로 막음).
- 새 토큰: `--chip`/`--chip-foreground`(기본은 secondary와 같음, shadcn `Badge` secondary 변형이 사용),
  `--ink`(항상 무채색인 진한 잉크, 기본 `--primary`와 같은 값). 대시보드·알림 메뉴의 알림 아이콘과 AI 사용량 막대는
  `--primary` 대신 `--ink`를 써서 메인이 무채색으로 남게 했다.
- 선택 UI(`color-theme-picker.tsx`)는 기본 + 프리셋 전부를 4열 카드 라디오 그룹으로(지금은 3장 — 4열 격자 첫 줄에 왼쪽부터 채워진다) 보여주고, 카드마다 주색/포인트/옅은 색 스와치를 둔다.
- 저장 키(`theme-color`)와 초기화 스크립트는 그대로이고, 예전 포인트색 값(`blue` 등)과 빠진 프리셋 id는 기본으로 떨어진다.

## 알려진 주의사항

- `pop-red`의 활성 메뉴(레드 박스 + `#111`)는 4.82:1로 기준에 가장 가깝다.
- 사이드바 섹션 라벨·사용자 이메일(`/70` 불투명도)은 3:1 이상이다 — 작은 보조 글자라 AA 대형 기준만 만족한다.
- 팔레트 값은 `theme.ts`와 `styles.css` 두 곳에 있다. 런타임 계산 대신 정적 CSS로 둬서 첫 페인트 전에 적용되게 한 대가이며,
  어긋나면 `theme.test.ts`가 잡는다. prettier가 CSS hex를 소문자로 바꾸므로 비교는 대소문자를 무시한다.
